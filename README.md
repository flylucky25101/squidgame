# LAST CITY · 목숨의 가격

## THE ISLAND · 경기장 모드 v3 (2026-09-10)

v3 업데이트: 무궁화꽃의 길 확보 버튼과 회전 예고를 제거하고, 무작위 박자의 한국어 구호·근접 카메라·플레이어 표식·영희 별도 화면·4.8초 피격 연출을 적용했습니다. 달고나는 상자를 열어 네 가지 모양 중 하나를 무작위로 공개합니다. 줄다리기는 근접 시점과 붉어지는 얼굴·땀·구호 말풍선을 추가했습니다. 제기차기는 위로 스와이프해 비석을 쓰러뜨리는 비석치기로 교체했으며, 빗나가면 돌을 회수해야 합니다. 유리다리는 유지했습니다. 마지막 경기는 선을 두껍게 그리고 카메라를 가까이 배치했으며, 이동 속도와 수비수 추격을 조정했습니다. 비석치기는 마우스/터치 스와이프 또는 Space를 눌렀다 떼서 던집니다. 달고나 랜덤 배정과 비석 단독 경기는 사용자 요청에 따른 각색입니다.

아래는 v2 구성 기록이며, 변경된 동작은 위 v3 설명을 따릅니다.

첫 화면에 독립 3D 경기장 모드를 추가했습니다. 기존 도시 게임은 상단 **도시 모드**에서 실행합니다.

- 무궁화꽃: 456명(플레이어 + NPC 455명) 전원 표시, 전체/근접 시점, 참가자 충돌과 길 확보, 무작위 비명·실랑이·멈칫함. 영희의 노란 상의·주황 원피스·양갈래 머리를 3D로 구현했습니다. 움직임 감지 후 사격·쓰러짐을 2.5초 보여주고 탈락 화면을 표시합니다. 제한 시간 5분.
- 설탕 뽑기: 원·세모·별·우산 선택 후 윤곽을 직접 드래그하여 분리합니다. 선을 벗어나면 표면이 손상되고 깨지면 탈락합니다. 제한 시간 10분.
- 줄다리기: 양쪽 10명씩 실시간으로 당기는 장면, 몸의 기울기·발 동작·땀방울·힘에 따른 위치 변화·패배 팀 추락을 표시합니다. 타이밍 조작 및 3분 제한은 싱글플레이용 각색입니다.
- 제기차기: 구슬 홀짝을 시즌 2의 제기차기로 교체했습니다. 내려오는 제기를 발 높이에서 5회 연속 차야 통과합니다. 땅에 닿으면 연속 횟수가 초기화되며 헛발질에는 복귀 시간이 있습니다. 시즌 2의 팀별 5종 경기 중 제기차기를 단독 경기로 각색했습니다.
- 유리다리: 18쌍의 유리, 고정 전체 시점, 실제 점프와 유리 파손·추락. 선택 가능한 기억 도움은 10초 동안 안전 발판을 연두색/✓로, 일반 유리를 분홍색/×로 표시합니다. 원작에는 정답 공개가 없으므로 보조 기능임을 안내하며 끌 수 있습니다. 제한 시간 16분.
- 오징어게임: 외발 이동으로 목을 횡단해 두 발 이동을 얻고, 바깥을 돌아 아래 입구로 들어가 머리의 원을 밟습니다. 경계 판정, 수비수 밀치기 예고, 밀치기·기력·경계 밖 패배를 구현했습니다. 목 통로 유도, AI, 기력 및 5분 제한은 게임용 각색입니다.

전체 6경기 연속 도전과 각 경기 연습을 지원합니다. PC는 WASD/방향키, 모바일은 아날로그 조이스틱으로 이동합니다. 캐릭터는 이동 방향을 봅니다. Space는 길 확보·줄다리기·제기차기·밀치기, 유리다리 Q/E는 좌/우, Esc는 일시정지입니다. 화면 전환·터치 취소·일시정지는 입력을 초기화합니다. 3D 모델은 자체 제작이며 실제 GTA 엔진이나 자산을 사용하지 않습니다. 온라인 대전·서버 저장은 없습니다.

원작 규칙 참고: [Netflix Tudum — Squid Game Games Explained](https://www.netflix.com/tudum/articles/squid-game-games-explained). 기본 승리 조건을 반영하되 모바일 조작과 싱글플레이를 위한 각색은 위에 구분했습니다.

정적 실행 및 배포:

```sh
pnpm exec vite --config vite.pages.config.mjs --host 0.0.0.0 --port 5173
pnpm exec vite build --config vite.pages.config.mjs
```

`dist-pages`가 정적 웹 배포 산출물입니다. `.github/workflows/pages.yml`은 main 푸시 때 GitHub Pages 빌드·배포를 수행합니다. 배포 저장소는 `flylucky25101/squidgame`, 공개 주소는 [THE ISLAND](https://flylucky25101.github.io/squidgame/)입니다. 이 폴더의 기존 `origin`은 도시 게임 저장소이므로 배포할 때 대상 저장소를 명시합니다.

게임 테스트는 참가자 수·충돌·지연 탈락·4종 윤곽·제기 연속 성공/실패·18칸 유리·목/입구/공격 단계·조이스틱 입력·가로/세로 카메라 투영을 검증합니다. TypeScript 검사와 정적 배포 빌드도 수행합니다. 실제 휴대전화의 프레임률·터치 감도는 기기 검증이 추가로 필요합니다.

해문시에서 차량을 탈취하고, 동맹을 맺고, 데스 게임을 통과해 조직을 성장시키는 **3D 브라우저 생존 액션 프로토타입**입니다.

## 현재 플레이할 수 있는 것

### 01.4 첫 성공과 전투 이해도 개선

- 튜토리얼 뒤 첫 배송 의뢰가 이어집니다. 지정 물품 확보 후 차량으로 은신처에 돌아와 정차하고 배송하면 1,000 C를 받습니다. 보상은 저장 프로필당 한 번 지급되며 대회 참가 시 미완료 배송은 취소됩니다. 제한 시간 없이 연습할 수 있습니다.
- 명중·제압 표시와 짧은 효과음, 피격 방향, 교전 중 적 체력 막대를 추가했습니다. 적 머리 위 주황색 표식은 0.65초 사격 준비를 뜻하며 엄폐하면 준비가 취소됩니다.
- 모바일 사격 버튼은 누르는 동안 연속 발사합니다. 황색·적색 신호에서는 연속 사격이 중단되며 녹색 신호에 다시 눌러야 합니다.
- 황색 신호 카운트다운에 경고음과 시각 강조를 추가했습니다. 무음 설정과 동작 줄이기 설정을 존중합니다.
- 탈락 화면에 실제 원인과 원인별 재도전 요령을 표시합니다. 모바일 화면의 상시 안내량은 늘리지 않고 첫 임무 안내와 짧은 전투 표시만 추가했습니다.

### 01.3 모바일 진입 경험 개선

- 왼쪽 아날로그 스틱으로 이동·가속·제동하고, 빈 화면을 드래그해 시점을 회전합니다. 이동과 시점 조작을 동시에 할 수 있습니다.
- 모바일 HUD는 체력, 탄약, 목표와 제한 시간을 중심으로 줄였습니다. 지도는 상단 지도 버튼으로 열고, 행동 버튼에는 확보·탑승·하차·장전·치료를 표시합니다.
- 일반 알림은 3.5초, 규칙 방송은 6.5초 뒤 사라집니다. 적색 신호와 타이머는 별도로 유지됩니다.
- 첫 도시 입장에서 안전한 이동·카메라·보관함·차량 연습을 안내합니다. 도시의 일시정지 메뉴에서 다시 시작하거나 언제든 건너뛸 수 있습니다. 연습에서는 체력을 회복하고 추적을 억제합니다. 대회 참가 시 연습은 종료됩니다.
- 캐릭터가 가려진 부분은 민트색 실루엣으로 표시하고, 캐릭터 주변을 덮는 간판 글씨는 숨깁니다.

자동 검증과 빌드는 수행했습니다. 실제 휴대전화의 터치 감도·프레임률·화면 배치는 기기별 플레이 검증이 추가로 필요합니다.

### 01.2 캐릭터·카메라 개선

- 둥근 신체 형태, 관절을 중심으로 움직이는 팔·다리와 무릎, 신발·장비·마스크 디테일을 추가했습니다.
- 실제 이동 속도에 맞춘 보행과 사격 자세를 적용했습니다. 정지한 NPC는 제자리걸음을 하지 않습니다.
- 건물이 시야를 막으면 카메라가 높이를 조절하고, 이동 중에도 건물 앞 안전한 위치를 유지합니다. 좁은 골목에서는 시야 확보를 위해 확대될 수 있습니다.
- 재시작할 때 이전 캐릭터의 그래픽 자원을 해제합니다.

### 01.1 업데이트

- 경쟁자가 증서 보관함을 선점하고 100개를 상환합니다. 소지자를 제압하면 미상환 증서를 회수할 수 있습니다.
- NPC는 건물을 돌아 목적지로 이동하며, 참가자는 황색·적색 신호에 정지합니다. 집행국은 통제자로서 계속 추적합니다.
- 동맹 윤서는 가까운 차량에 동승하고 함께 내립니다. 멀리 뒤처졌다면 속도를 줄여 기다려 주세요.
- 적색 신호 중 제동을 계속 눌러도 정지 후 후진하지 않습니다.
- 회수 가능한 증서가 100개 미만이면 패배 사유를 알리고 대회를 종료합니다.

대회 단계 전환은 플레이어 기준인 싱글플레이 규칙입니다. 경쟁자의 별도 결승 진출이나 온라인 대진표는 아직 구현하지 않았습니다.

- 건물과 충돌하는 3D 도시 탐험, 카메라 회전·줌, 전체 지도·미니맵
- 12대의 차량 탈취, 가속·제동·후진·조향, 부스트와 차량 내구도
- 권총 조준·사격·재장전, 탄약과 의료품, 집행국의 추적
- 경쟁 NPC 12명, 집행국 6명, 협력자 윤서
- 윤서와의 동맹, 전투 지원·전력 복구 시 치료, 공동 배당과 배신
- **연대채무 → 도시의 심장 → 마지막 배당**의 연속 대회
- 적색 신호의 행동 제한과 예고되는 VIP 정전
- 우승 상금, 정비소·진료소·정보망 구매, 세력 선택과 영향력
- 참가자의 영구 퇴장과 조직 자산·기록의 브라우저 자동 저장
- 일시정지, 소리·화면 흔들림·저사양 설정, 기본 터치 조작

## 실행

Node.js 22.13 이상과 pnpm을 사용합니다.

```sh
pnpm install
pnpm dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 엽니다. WebGL2와 하드웨어 가속을 지원하는 데스크톱 브라우저를 권장합니다.

```sh
pnpm test       # 게임 규칙 회귀 테스트
pnpm typecheck  # TypeScript 검사
pnpm build     # 배포 빌드
pnpm start     # 생성된 Worker의 로컬 실행
```

패키지 설치 스크립트의 허용 여부는 `pnpm-workspace.yaml`에 명시되어 있습니다. 사전 빌드된 플랫폼 패키지를 사용합니다.

## 대회

1. **연대채무 · 210초:** 보관함에서 증서 100을 모아 중앙 상환소에 납부합니다. 녹색 25초, 황색 3초, 적색 7초가 반복됩니다. 적색 중 추진·조향·발포는 25 피해를 주며 2초의 재판정 간격이 있습니다. 제동과 관성 이동은 허용됩니다.
2. **도시의 심장 · 210초:** 서로 다른 변전소 3곳을 복구합니다. 정전은 미리 고지됩니다. 살아 있는 동맹이 있으면 복구 때 체력을 회복합니다.
3. **마지막 배당 · 150초:** 북동쪽 항만의 회수 차량에 도착해 E로 탈출합니다. 단독 배당은 20,000 C, 살아 있는 동맹과의 공동 배당은 10,000 C입니다.

도시에서는 밀수품으로 자금을 얻고 은신처에서 회복할 수 있습니다. 일반 도시의 패배는 응급 구조비를 차감하고, 대회의 패배는 참가자를 영구 퇴장시킵니다. 기존 조직의 자금과 시설은 유지됩니다.

## 저장

조직 정보는 이 브라우저의 `localStorage`에 저장됩니다. 서버 계정 저장·기기 간 동기화는 없습니다. 진행 중인 대회는 새로고침하면 종료됩니다. 브라우저 데이터를 삭제하면 조직 저장도 사라집니다.

## 구조

```text
app/game/model.js       게임 상태, 규칙, 경제, 충돌, NPC 로직
app/game/engine.js      Three.js 도시·캐릭터·차량, 입력, 카메라, 효과음
app/game/LastCity.tsx   시작 화면, HUD, 지도, 설정, 조직 관리
app/globals.css         전체 인터페이스와 반응형 레이아웃
tests/model.test.mjs    진행·정산·사망·차량·저장·전투 회귀 테스트
```

기술: React 19, Three.js, TypeScript, Vite/Vinext, Tailwind CSS, Base UI/Shadcn. 도시는 코드로 생성하며 외부 이미지나 유료 API는 필요하지 않습니다.

## 구현 범위

이 저장소는 기획의 핵심 순환을 플레이할 수 있도록 만든 싱글플레이 수직 슬라이스입니다. AAA 완성작이나 온라인 멀티플레이 서비스는 아닙니다. 실제 플레이어 매칭, 권위 서버, 공동 거래 원장, 시즌 영토전, 거대한 연속 도시, 완전한 NPC 사회·경쟁 시뮬레이션은 아직 구현되지 않았습니다.

원래 기획의 50~70분 대회는 이 버전에서 최대 9분 30초로 축약했습니다. NPC 수, 장비, 부동산과 세력 시스템도 구현 범위에 맞게 축소했습니다. 저장 데이터는 로컬 게임용으로 신뢰되며 온라인 경쟁이나 현금 거래에 사용할 수 없습니다.

## 검증

게임 모델 회귀 테스트와 TypeScript 검사, 프로덕션 빌드를 수행합니다. 브라우저별 그래픽 품질과 실제 플레이 체감에 대한 수동 QA는 별도 검증이 필요합니다.

## 배포

`.openai/hosting.json`은 소유자의 Sites 배포 프로젝트를 가리킵니다. 다른 계정에 복제한 뒤에는 자신의 배포 대상에 맞게 설정해야 합니다. 인증 토큰과 비밀 키는 저장소에 포함하지 않습니다.
